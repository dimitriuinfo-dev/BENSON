## Stale-result display bug (found during review, not yet fixed)

At ~17:08 the app displayed "Am încercat să deschid Rechner… mobi.drupe.app" as if current. Traced: this was the ORIGINAL 17:01:38 Calculator-open mission's own delayed async foreground-check, which had been blocked behind the WhatsApp call's mission-gate state and only resumed and reported (`STATE IDLE→CONFIRMING detail=mission_gate`) the instant the call ended (17:07:35.921) — by which point the phone's actual foreground app had moved on to the post-call dialer screen (`mobi.drupe.app`), making the reported mismatch stale and misleading. Evidence: `scratchpad/drupe_check.txt` lines 341–393. **Not fixed** — root cause (a delayed mission result rendering as if it reflects the current operation) needs a turn/mission-identity guard before display, not an executor change.
